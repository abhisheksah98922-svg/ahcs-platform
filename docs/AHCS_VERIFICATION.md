# AHCS — Identity & Document Verification Architecture

## 1. Overview & Verification Philosophy

AHCS issues real healthcare identity credentials. As such, account creation alone does not authorize the generation of an AHCS Client ID or Health Card. A rigorous verification pipeline ensures identity validity, document authenticity, and duplicate prevention.

---

## 2. Verification Lifecycle State Machine

```
   ┌─────────┐
   │  DRAFT  │ (User uploading documents)
   └────┬────┘
        │ Submit
        ▼
   ┌───────────┐
   │ SUBMITTED │ (Queued for verification)
   └─────┬─────┘
         │ Automated Duplicate Check
         ▼
   ┌──────────────┐
   │ UNDER_REVIEW │ ── Assigned to Verification Officer
   └──────┬───────┘
          ├─────────────────────────┬───────────────────────────┐
          │ Approve                 │ Request Correction         │ Reject
          ▼                         ▼                           ▼
   ┌──────────┐            ┌─────────────────────────┐    ┌──────────┐
   │ VERIFIED │            │ RE_VERIFICATION_REQUIRED│    │ REJECTED │
   └──────────┘            └─────────────────────────┘    └──────────┘
```

## 3. Supported Identity Documents (Configurable)

The platform supports administrator-configurable document schemas. Default accepted types:
* **Passport**: High reliability, international travel reference.
* **Driving Licence**: State transport authority issued photo ID.
* **Voter ID (EPIC)**: Election commission electoral photo identity card.
* **National ID / Aadhaar**: Accepted as an identity document where legally permitted. **AHCS is NOT an Aadhaar replacement and never stores full biometric or unnecessary demographic data.**
* **Other Officially Accepted Documents**: Admin configured (e.g., PAN Card for financial/tax verification where appropriate).

### Document Storage & Privacy
* The document number is never stored as plaintext in indexing columns. Instead:
  * `document_number_hash = SHA256(doc_type + normalized_doc_number)` (Used for duplicate matching).
  * `document_number_masked` (e.g. `XXXX-XXXX-8921` for human review).
* The raw document file is encrypted via AES-256 and stored in a private S3 bucket.
* Viewing a document in the Verification Officer Panel generates a short-lived (60-second) pre-signed URL. Public downloads are strictly blocked.

## 4. Verification Officer Role & Controls

The Verification Officer is a vetted staff role with access to the `/officer/verification` portal.

### Review Checklist:
1. **Name Match**: Compare legal name on submitted document against the AHCS profile name.
2. **DOB Match**: Ensure exact date of birth alignment.
3. **Photo & Clarity**: Ensure document scan is uncropped, high-resolution, unedited, and not expired.
4. **Duplicate Warning**: Officer must review any system flags generated by the Duplicate Detection Engine.

### Officer Actions:
* **`Approve`**: Marks document `VERIFIED`. Once all required documents are verified, the profile status transitions to `APPROVED_FOR_ID_GENERATION`.
* **`Reject`**: Marks document `REJECTED` with mandatory structured rejection reason (e.g., `DOCUMENT_EXPIRED`, `NAME_MISMATCH`, `FRAUDULENT_DOCUMENT`).
* **`Request Correction`**: Notifies user to re-upload with specific officer guidance notes.
* **Every action is immutable and logged** in `verification_events` and `audit_logs` with officer ID, timestamp, and justification.
